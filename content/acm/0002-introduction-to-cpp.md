## ACM 简介 {#acm-简介}

ACM国际大学生程序设计竞赛（ACM International Collegiate Programming Contest，简称ACM-ICPC）是世界上规模最大、水平最高的国际性大学生程序设计竞赛，被誉为"程序设计的奥林匹克"。该竞赛由美国计算机协会（ACM）于1977年发起，至今已有40多年的历史。从最初只有几所美国大学参与，到如今每年有来自六大洲100多个国家和地区的数千所大学、数万名学生参与，ACM-ICPC已经成为全球最受关注和最具影响力的大学生学术竞赛之一。


### 竞赛背景 {#竞赛背景}

ACM-ICPC的核心理念是展示大学生创新能力、团队精神和在压力下编写程序、分析和解决问题的能力。该竞赛不仅是一项智力竞赛，更是一个培养未来计算机科学家和工程师的重要平台。许多知名科技公司如Google、Facebook、Microsoft、阿里巴巴、腾讯等都将ACM经历作为招聘算法工程师和软件开发工程师的重要参考因素。

比赛采用三人组队的形式，每支队伍使用一台计算机，在5小时的高强度比赛中，使用C++、Java、Python等编程语言解决8-13道算法题目。这些题目涉及数据结构、算法、数学、图论、动态规划等多个领域，难度从简单到极难不等。竞赛不仅考察选手的编程能力，更注重算法思维、问题分析、团队协作和临场应变能力。选手需要在有限的时间内快速理解题目、设计算法、编写代码、调试排错，这对选手的综合素质提出了极高的要求。


### 比赛流程和规则 {#比赛流程和规则}

ACM-ICPC的完整比赛流程包括多个层级：

1.  **网络赛/校内赛** ：各大学自行组织的选拔赛，通常是接触ACM的第一站。校内赛难度适中，帮助选手熟悉比赛规则和流程，优秀队伍晋级省赛或区域赛。

2.  **区域赛（Regional Contest）** ：亚洲、欧洲、美洲等各大洲举行的多场区域赛。亚洲区包括亚洲区域赛（南宁站、上海站、沈阳站、青岛站等）、EC-Final等。区域赛是通往世界总决赛的关键站点，只有获得金奖、银奖、铜奖的队伍才有资格参加世界总决赛的选拔。

3.  **世界总决赛（World Finals）** ：全球最顶尖的队伍通过区域赛的选拔，最终约100-120支队伍参加世界总决赛。世界总决赛通常在每年的5-6月举办，地点遍布世界各地，参赛队伍大多是各大洲区域赛的冠军队伍。

比赛规则细节：

-   每队3人，使用1台计算机，强制要求团队合作
-   比赛时间通常为5小时，全程高强度的脑力消耗
-   不允许携带任何电子设备，只能使用比赛提供的系统和少量参考资料
-   可以使用C++、C、Java、Python、Kotlin等编程语言，其中C++是最主流的选择
-   提交答案后，评测机会在几分钟内给出结果，选手可以根据反馈修改代码
-   题目难度梯度明显，通常有2-3道简单题、4-5道中等题、2-3道困难题
-   比赛过程中可以随时查看实时排行榜，了解其他队伍的通过情况和进度
-   气球是ACM比赛的标志性元素，每队每通过一题，工作人员就送一个对应颜色的气球


### 比赛中的团队协作 {#比赛中的团队协作}

ACM是团队比赛，良好的团队协作是成功的关键。很多个人能力很强的选手组队后却表现不佳，原因就是缺乏有效的团队协作。

1.  **角色分工**
    -   主力手：负责编写核心算法代码，通常编程速度最快、代码风格最规范的队员
    -   思考者：负责分析题目、设计算法思路，通常数学功底扎实、算法思维强的队员
    -   调试员：负责查找代码错误、编写测试用例，通常细心耐心、善于发现问题的队员
    -   在实际比赛中，角色分工不是固定的，会根据题目特点和队员状态灵活调整

2.  **协作技巧**
    -   遇到卡题及时讨论，不要一个人死磕太久，浪费时间
    -   编码时旁边的人帮忙检查语法错误和逻辑漏洞，提高编码效率
    -   完成一题后，三名队员一起讨论下一题的选择，分析难度和性价比
    -   保持良好的沟通氛围，互相鼓励不抱怨，保持团队士气
    -   当时间紧张时，要合理安排做题顺序，优先解决相对简单且得分高的题目
    -   如果有队伍已经通过了某题，可以参考他们的策略和思路

3.  **心态管理**
    -   比赛过程中保持冷静，不要因为一题卡住而影响其他题的心态
    -   错误提交不要气馁，仔细分析错误原因，不要盲目重交
    -   相信队友的判断，团结一致，不要互相指责
    -   最后一小时是冲刺时间，不要轻易放弃，即使时间不够也要尽可能多得分
    -   保持积极心态，享受比赛过程，无论成绩如何都是宝贵的经验


### 算法竞赛的三大赛制 {#算法竞赛的三大赛制}

算法竞赛主要分为三种赛制：ACM赛制、OI赛制和IOI赛制，每种赛制有独特的评分规则和比赛方式。


#### ACM赛制 {#acm赛制}

ACM赛制是国际大学生程序设计竞赛（ICPC）和中国大学生程序设计竞赛（CCPC）等正式比赛采用的传统赛制，也是算法竞赛中最主流的赛制。ACM赛制强调"零和博弈"，要么完全正确，要么完全错误，没有中间状态。

特点详解：

-   **严格评判** ：只有正确和错误两种结果，即使通过了99个测试点，只要有1个测试点不通过，结果就是错误（WA）
-   **有限反馈** ：可以看到程序的运行结果，但无法了解具体测试点的情况，不知道哪个测试点没通过
-   **无限提交** ：题目可以不限次数提交，选手可以反复修改代码
-   **罚时机制** ：每次错误提交会有20分钟罚时，错误尝试越多罚时越重
-   **实时排名** ：可以看到实时的排行榜，选手可以了解其他队伍的通过情况和进度
-   **气球机制** ：每通过一题就会有一个对应颜色的气球，气球颜色通常对应题目顺序，如A题对应红色、B题对应蓝色等

排名方式详解：

1.  **第一优先级** ：通过题目数量，通过题目越多排名越靠前
2.  **第二优先级** ：通过题数相同时，按总罚时升序排序，罚时越少排名越高

罚时计算详解：
每道题的罚时 = 解题用时 + 错误尝试次数 × 20分钟

总罚时 = 所有题目的罚时之和

详细示例：
假设比赛进行了120分钟

队伍A的情况：

-   30分钟通过A题，之前有2次错误提交 → A题罚时 = 30 + 2×20 = 70分钟
-   60分钟通过B题，之前有1次错误提交 → B题罚时 = 60 + 1×20 = 80分钟
-   解了2题，总罚时 = 70 + 80 = 150分钟

队伍B的情况：

-   20分钟通过A题，之前有3次错误提交 → A题罚时 = 20 + 3×20 = 80分钟
-   40分钟通过B题，之前有2次错误提交 → B题罚时 = 40 + 2×20 = 80分钟
-   解了2题，总罚时 = 80 + 80 = 160分钟

结果：尽管队伍B在两道题上解题时间都更快，但因为错误次数多，总罚时更高，排名落后于队伍A。

ACM赛制实战策略：

1.  **题号分析** ：优先解决标为A、B、C的题目，这些通常是简单题，容易得分
2.  **时间管理** ：前2小时集中解决4-5道简单题和中等题，后3小时攻坚难题
3.  **谨慎提交** ：不要盲目提交，如果不确定答案，可以在本地进行更多测试
4.  **观察榜单** ：关注其他队伍的通过情况，一题被很多队伍通过时，说明难度较低
5.  **团队合作** ：一人编码时，另外两人应该思考下一道题，不浪费任何时间
6.  **最后1小时** ：如果还有未通过的题目，可以更加冒险地尝试，因为错过一题的机会成本很高

常见ACM赛制比赛：

-   **ICPC国际总决赛** ：每年一次，全球顶尖队伍参赛
-   **ICPC亚洲区域赛** ：亚洲地区每年举办多站区域赛（南宁、上海、沈阳、青岛、EC-Final等）
-   **CCPC中国大学生程序设计竞赛** ：中国的官方程序设计竞赛
-   **CCPC各省赛/省选拔赛** ：各省市的CCPC选拔赛
-   **Codeforces Div.1/Div.2/Div.3比赛** ：定期举办的在线比赛
-   **LeetCode周赛/双周赛** ：每周/每两周举办的算法竞赛
-   **牛客周赛/小白月赛/练习赛/挑战赛** ：牛客平台举办的各种比赛


#### OI赛制 {#oi赛制}

OI赛制源于全国青少年信息学奥林匹克联赛（NOI），是中国信息学竞赛的主要赛制，采用部分得分制。与ACM赛制的"非黑即白"不同，OI赛制允许部分得分，即使没有完全解决问题，也能获得部分分数。

特点详解：

-   **无反馈机制** ：提交后没有任何测试结果反馈，选手无法知道自己的程序通过了哪些测试点，以最后一次提交为准
-   **无实时排名** ：比赛过程中没有实时排行榜，选手不知道自己的排名情况，需要凭感觉判断自己的水平
-   **部分得分** ：每道题的多个测试点各有相应分数，通常每个测试点占5-20分，通过一个测试点得一个测试点的分
-   **累计分数** ：总分为所有题目获得分数之和，不是通过题目数量
-   **提交次数** ：可以多次提交，但只有最后一次提交有效
-   **赛后评测** ：比赛结束后统一评测，公布最终排名和每道题的得分情况

排名方式详解：
按照总分进行降序排序，总分越高的队伍排名越靠前。如果总分相同，则比较更高分的题目数量或特定题目的得分情况。

OI赛制的测试点通常有以下特点：

1.  **小数据测试点** ：数据规模小，适合暴力算法，容易得分
2.  **中等数据测试点** ：数据规模中等，需要优化算法
3.  **大数据测试点** ：数据规模大，需要最优算法，分值最高

关键策略详解：

1.  **骗分策略** ：OI赛制最独特的策略就是"骗分"，通过不完全正确的算法获得部分分数
    -   **打表法** ：手动计算出小规模数据的答案，在程序中直接输出预计算的结果
    -   **暴力枚举** ：使用时间复杂度高的算法解决小规模数据
    -   **特判法** ：判断一些特殊情况，如n=0、n=1等，直接给出答案
    -   **贪心法** ：使用简单的贪心算法，虽然是错误的，但能通过部分测试点
    -   **随机化** ：在无法确定正确答案时，随机输出一个合理范围内的数

2.  **分治策略** ：
    -   首先编写最简单的暴力算法，确保能拿到小数据点的分数
    -   然后逐步优化算法，争取通过更多测试点
    -   最后尝试最优算法，但即使失败也能保证部分分数

3.  **时间分配** ：
    -   前期快速浏览所有题目，判断每道题的难度和可行性
    -   优先解决能通过大数据点的题目
    -   对于困难的题目，至少保证通过小数据点
    -   不要在一道题上花费太多时间，部分得分也很重要

4.  **样例利用** ：
    -   仔细分析样例的输入输出，观察规律
    -   样例通常是简单的测试点，要确保通过样例测试

常见OI赛制比赛：

-   **CCF CSP计算机软件能力认证** ：全国性的计算机软件能力测试，每年多次举行，是很多公司招聘的参考标准
-   **CCF NOIP全国青少年信息学奥林匹克联赛** ：中学生信息学竞赛的最高级别
-   **CCF NOI全国青少年信息学奥林匹克竞赛** ：全国中学生信息学竞赛决赛
-   **蓝桥杯** ：全国性的软件类竞赛，分多个组别
-   **CCF CSP-J/S认证** ：面向中小学生的计算机软件能力认证
-   **牛客OI集训营** ：牛客平台举办的OI赛制练习赛和比赛
-   **各省市信息学竞赛** ：省市级的OI赛制选拔赛


#### IOI赛制 {#ioi赛制}

IOI赛制是国际信息学奥林匹克竞赛（International Olympiad in Informatics）采用的赛制，结合了ACM赛制和OI赛制优点的新型赛制。IOI赛制既像ACM赛制一样有实时反馈和实时排名，又像OI赛制一样允许部分得分，是目前最友好、最适合初学者的赛制。

特点详解：

-   **有反馈机制** ：提交后立即反馈结果，可以看到本题通过了哪些测试点，每个测试点的得分情况
-   **实时排名** ：有实时排行榜显示各队伍/选手的得分情况，选手可以了解自己的位置
-   **无罚时限制** ：可以反复提交，没有罚时，不用担心错误提交带来的惩罚
-   **最高分数制** ：按每道题的所有提交中的最高得分计算最终成绩，即使多次提交，只会取最好的一次
-   **透明度高** ：选手可以清楚地知道自己每道题的得分情况，以及还有多少分可以通过优化获得
-   **灵活性** ：比赛过程中可以随时调整策略，根据已有分数决定接下来的重点

排名方式详解：
每道题按所有提交中的最高得分计算，所有题目得分相加得到总分，按总分实时排名。相比ACM赛制，IOI赛制的排名更加直观，分数越高排名越靠前。

IOI赛制的测试点设置：

-   IOI赛制通常有多个子任务（Subtask），每个子任务包含多个测试点
-   每个子任务有明确的分数，通常子任务1是10-20分，子任务2是20-30分，子任务3是30-50分
-   子任务之间是递进关系，通常子任务1的数据规模最小，后续子任务数据规模逐渐增大
-   通过了一个子任务的所有测试点，才能获得该子任务的全部分数

关键策略详解：

1.  **暴力优先** ：IOI赛制最适合暴力枚举和打表骗分
    -   先写最简单的暴力算法，确保能拿到第一子任务的分数
    -   不要一开始就追求最优算法，即使是最暴力的算法也能得分
    -   部分分数总比没有分数好

2.  **逐步优化** ：
    -   先通过部分测试点获得基础分，再逐步优化算法
    -   每次优化后提交，看看能通过更多测试点
    -   即使最终未通过大数据点，也能保证小数据点的分数

3.  **最后冲刺** ：
    -   允许在最后时刻提交最优解，不用担心罚时
    -   比赛最后几分钟，可以尝试冒险提交最新优化的代码
    -   即使错了也不会影响之前的得分

4.  **时间分配** ：
    -   比赛初期快速浏览所有题目，判断每道题的难度和可行性
    -   优先解决第一子任务容易拿分的题目
    -   中期开始优化算法，争取通过更多子任务
    -   后期可以根据实时排名调整策略，优先优化能获得更高分数的题目

5.  **调试技巧** ：
    -   充分利用反馈信息，看看自己通过了哪些测试点，没通过哪些
    -   根据未通过测试点的特点分析自己的算法哪里有问题
    -   可以通过构造边界数据来测试自己的代码

与ACM和OI赛制的对比：

| 特点 | ACM赛制   | OI赛制 | IOI赛制     |
|----|---------|------|-----------|
| 反馈 | 有（AC/WA等） | 无     | 有（详细分数） |
| 实时排名 | 有        | 无     | 有          |
| 罚时 | 有        | 无     | 无          |
| 部分得分 | 无        | 有     | 有          |
| 提交计算 | 最后一次有效 | 最后一次有效 | 最高分有效  |
| 适合人群 | 高水平选手 | 中高水平选手 | 所有选手，特别是初学者 |

常见IOI赛制比赛：

-   **IOI国际信息学奥林匹克竞赛决赛** ：全球最高水平的中学生信息学竞赛
-   **洛谷入门赛** ：洛谷专门为初学者举办的入门比赛，题目简单，适合新手练手
-   **洛谷月赛** ：洛谷每月举办的月赛，分为提高组和普及组，难度适中
-   **拼题A（PTA）** ：浙江大学主办的程序设计教学平台，举办多种IOI赛制比赛
-   **GPLT团体程序设计天梯赛** ：团体程序设计比赛，注重团队合作
-   **CCF CCSP** ：CCF主办的CCSP（计算机系统与程序设计竞赛）
-   **牛客周赛** ：牛客平台每周举办的比赛，难度适中
-   **Codeforces Edu Round** ：Codeforces的教育轮比赛，难度较低，适合新手


### 算法竞赛题目形式 {#算法竞赛题目形式}

算法竞赛的一道题目通常由以下六个核心部分组成，每个部分都有其独特的作用：

1.  **题目描述（Description）** ：题目背景、故事描述、操作步骤说明，部分概念的定义和解释
    -   题目可能会用一个故事来包装算法问题，让题目更有趣味性
    -   需要从描述中提取出数学模型或算法问题的本质
    -   一些特殊的定义和术语会在本部分说明
    -   需要仔细阅读，理解题目要解决的核心问题

2.  **输入描述（Input）** ：输入格式、输入变量说明、输入数据范围
    -   详细说明输入数据的格式，如第一行有几个数，每个数代表什么
    -   每个变量的取值范围对确定算法时间复杂度至关重要
    -   数据规模决定了使用什么时间复杂度的算法
    -   特殊情况如多组测试数据、文件结束等也会在这里说明
    -   数据范围是判断算法可行性的重要依据

3.  **输出描述（Output）** ：输出结果的格式、输出内容，需要严格按照要求输出
    -   输出格式要求严格，多一个空格或少一个换行都可能导致PE
    -   需要输出什么内容，是数字、字符串还是其他类型
    -   输出格式是否需要特定顺序，如升序、降序
    -   是否有特殊情况需要处理，如无解时输出-1等

4.  **输入样例（Sample Input）** ：一组或多组满足输入描述格式的数据
    -   样例是最直观的测试用例，有助于理解题目
    -   样例通常是简单的情况，但包含了题目的一般特征
    -   可以在本地用样例测试自己的程序
    -   样例通过了不代表程序正确，但样例不通过说明程序一定有问题

5.  **输出样例（Sample Output）** ：输入样例对应的正确输出结果，用于验证程序
    -   输出样例的标准答案，用来检验程序的输出是否正确
    -   注意观察输出的格式、数值、顺序等细节
    -   可以手动计算验证样例的正确性

6.  **更多信息（More Information）** ：对样例的解释说明，或者变量的取值范围，可能透露解题思路
    -   对复杂样例的解释，帮助选手理解题意
    -   更多限制条件或特殊的注意事项
    -   可能会提示解题的关键思路或数据结构
    -   时有时无，但如果有，通常很重要

解题流程：

1.  仔细阅读题目描述，理解问题本质
2.  查看输入输出格式和数据范围
3.  分析样例，理解输入输出的对应关系
4.  设计算法，考虑时间复杂度是否在可接受范围内
5.  编写代码，实现算法
6.  用样例测试程序
7.  提交代码，根据评测结果进行调试


### 常见评测状态 {#常见评测状态}

在提交程序后，评测系统会运行并测试程序，返回评测结果。常见的评测状态包括：

-   **AC (Accept)** ：程序通过所有测试点，答案正确。这是最理想的状态，表明你的程序完全符合题目要求。

-   **CE (Compile Error)** ：编译错误，代码中有语法错误或编译问题。
    -   常见原因：缺少分号、括号不匹配、变量未声明、头文件错误等
    -   解决方法：查看编译错误信息，根据提示修改代码
    -   注意：CE不会计入提交次数和罚时

-   **WA (Wrong Answer)** ：答案错误，程序运行了但输出结果不正确。
    -   常见原因：算法错误、边界条件处理不当、输出格式错误、变量类型错误等
    -   解决方法：仔细检查算法逻辑，考虑边界情况，检查变量类型是否足够大
    -   技巧：构造小规模数据手动验证，用调试器逐行跟踪

-   **RE (Runtime Error)** ：运行时错误，程序运行过程中的异常导致崩溃。
    -   常见原因：数组越界、空指针访问、除零错误、栈溢出、动态内存分配失败等
    -   解决方法：检查数组大小是否足够，检查指针是否为空，避免除零
    -   技巧：在本地运行程序，使用调试器找到崩溃的位置

-   **TLE (Time Limit Exceeded)** ：超出时间限制，程序运行时间超过了题目规定的时间限制。
    -   常见原因：算法时间复杂度过高、死循环、常数过大（如IO操作太多）等
    -   解决方法：优化算法，降低时间复杂度；使用快速IO；避免不必要的计算
    -   技巧：根据数据范围判断时间复杂度是否合理；使用剪枝等优化技巧

-   **MLE (Memory Limit Exceeded)** ：超出内存限制，程序使用的内存超过了题目限制。
    -   常见原因：数组过大、动态内存分配过多、递归过深导致栈溢出等
    -   解决方法：减小数组大小；使用更节省空间的数据结构；优化内存使用
    -   技巧：使用vector动态数组；及时释放不再使用的内存

-   **PE (Presentation Error)** ：格式错误，答案基本正确但输出格式有问题。
    -   常见原因：多空格或少空格、多换行或少换行、大小写错误、输出顺序错误等
    -   解决方法：仔细对比输出样例，严格按照格式要求输出
    -   注意：PE在某些评测系统会算作错误，需要谨慎
    -   技巧：使用printf或cout精确控制输出格式

-   **PC (Partially Correct)** ：部分正确（OI/IOI赛制），通过了部分测试点但未通过全部测试点。
    -   说明 ：你的算法通过了部分测试点，获得了部分分数
    -   原因 ：算法可能只适用于部分数据规模，或者存在某些特殊情况未处理
    -   技巧 ：这是IOI赛制中常见状态，可以作为优化方向

-   **OLE (Output Limit Exceeded)** ：输出超过限制，输出的内容过多。
    -   常见原因 ：死循环导致无限输出、输出语句放在循环中、逻辑错误导致大量输出
    -   解决方法 ：检查输出语句的位置，避免死循环

-   **UKE (Unknown Error)** ：未知错误，评测系统内部错误。
    -   说明：这是评测系统的问题，通常是临时的网络或服务器问题
    -   处理：等待一段时间后重新提交
    -   注意：UKE不计入提交次数

常见错误的排查技巧：

1.  **先看CE** ：编译错误最简单，先解决语法问题
2.  **样例测试** ：本地运行样例，看看是否通过
3.  **小规模数据** ：手动构造小规模数据，验证程序逻辑
4.  **边界情况** ：检查0、1、最大值、最小值等边界情况
5.  **分步调试** ：使用调试器或输出中间结果，定位错误
6.  **查阅题解** ：实在不会时，可以参考题解学习思路

## 程序的基本结构 {#程序的基本结构}


### 程序的三种基本执行方式 {#程序的三种基本执行方式}

任何程序都可以由三种基本结构组成：

1.  **顺序执行** ：代码按从上到下的顺序执行
2.  **分支语句** ：根据条件选择执行不同代码
3.  **循环语句** ：重复执行某段代码

一个完整的程序就是这三种结构的组合。


### 程序的基本框架 {#程序的基本框架}

ACM中的C++程序通常有固定的结构：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 你的代码
    return 0;
}
```


### 顺序执行示例 {#顺序执行示例}

顺序执行是最基本的结构，代码按顺序逐行执行：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int a ;          // 1. 定义变量并赋值
    int b ;          // 2. 定义另一个变量
    cin >> a >> b;   // 3. 输入 a 和 b 的值
    int sum = a + b; // 4. 计算和
    cout << sum;     // 5. 输出结果

    return 0;
}
```

这五行代码按顺序执行：先执行第1行，再执行第2行，依此类推。

### [P5708 【深基2.习2】三角形面积 - 洛谷](https://www.luogu.com.cn/problem/P5708) {#p5708-深基2-dot-习2-三角形面积-洛谷}


#### 题目描述 {#题目描述}

一个三角形的三边长分别是 \\(a\\)、\\(b\\)、\\(c\\)，那么它的面积为 \\(\sqrt{p(p-a)(p-b)(p-c)}\\)，其中 \\(p=\frac{1}{2}(a+b+c)\\)。输入这三个数字，计算三角形的面积，四舍五入精确到 \\(1\\) 位小数。


#### 输入格式 {#输入格式}

第一行输入三个实数 \\(a,b,c\\)，以空格隔开。


#### 输出格式 {#输出格式}

输出一个实数，表示三角形面积。精确到小数点后 \\(1\\) 位。


#### 输入输出样例 #1 {#输入输出样例-1}


##### 输入 #1 {#输入-1}

```text
3 4 5
```


##### 输出 #1 {#输出-1}

```text
6.0
```


#### 说明/提示 {#说明-提示}

数据保证能构成三角形，\\(0\leq a,b,c\leq 1000\\)，每个边长输入时不超过 \\(2\\) 位小数。


#### 代码 {#代码}

```C++
#include <bits/stdc++.h>

using namespace std;
int main(int argc, char *argv[])
{
    double a,b,c;
    cin >> a >> b >> c;
    double p = (a + b + c) * 0.5;
    cout << fixed << setprecision(1) << sqrt(p*(p-a)*(p-b)*(p-c)) << endl;
    return 0;
```

### 完整的例子：统计数字出现次数 {#完整的例子-统计数字出现次数}

输入一个数字n，统计1到n中数字0-9出现的次数。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;

    // 【顺序执行】初始化计数器数组
    int count[10] = {0};  // 所有元素初始化为0

    // 【循环语句】遍历1到n的所有数字
    for (int i = 1; i <= n; i++) {
        int temp = i;

        // 【嵌套循环】分离每一位数字
        while (temp > 0) {
            int digit = temp % 10;  // 获取最后一位
            count[digit]++;         // 对应数字计数加1
            temp /= 10;              // 去掉最后一位
        }
    }

    // 【顺序执行】输出结果
    for (int i = 0; i < 10; i++) {
        if (count[i] > 0) {
            // 【分支语句】只输出出现的数字
            cout << "数字" << i << "出现" << count[i] << "次" << endl;
        }
    }

    return 0;
}
```

这个程序展示了三种结构的完整组合：

-   **顺序执行** ： 变量声明、初始化、输出
-   **分支语句** ： `if` 条件判断

识别码的计算方法如下：

首位数字乘以 \\(1\\) 加上次位数字乘以 \\(2\\) ......以此类推，用所得的结果  \\(\bmod 11\\)  ，所得的余数即为识别码，如果余数为 \\(10\\)，则识别码为大写字母 \\(X\\)。例如 ISBN 号码 `0-670-82162-4` 中的识别码 \\(4\\) 是这样得到的：对 `067082162` 这 \\(9\\) 个数字，从左至右，分别乘以 \\(1,2,\dots,9\\) 再求和，即 \\(0\times 1+6\times 2+……+2\times 9=158\\)，然后取 \\(158 \bmod 11\\) 的结果 \\(4\\) 作为识别码。

```cpp
                    if (num >= a && num <= b && isPrime(num))
                    {
                        palindromicPrimes.push_back(num);
                    }
                }
            }
        }
    }

    return palindromicPrimes;
}

int main()
{
    int a, b;
    cin >> a >> b;

    // 生成回文质数
    vector<int> palindromicPrimes = generatePalindromicPrimes(a, b);

    // 输出结果
    for (int num : palindromicPrimes)
    {
        cout << num << endl;
    }

    return 0;
}
```


### [P5723 【深基4.例13】质数口袋 - 洛谷](https://www.luogu.com.cn/problem/P5723) {#p5723-深基4-dot-例13-质数口袋-洛谷}


#### 题目描述 {#题目描述}

小 A 有一个质数口袋，里面可以装各个质数。他从 \\(2\\) 开始，依次判断各个自然数是不是质数，如果是质数就会把这个数字装入口袋。

口袋的负载量就是口袋里的所有数字之和。

但是口袋的承重量有限，装的质数的和不能超过 \\(L\\)。给出 \\(L\\)，请问口袋里能装下几个质数？将这些质数从小往大输出，然后输出最多能装下的质数的个数，数字之间用换行隔开。


#### 输入格式 {#输入格式}

一行一个正整数 \\(L\\)。


#### 输出格式 {#输出格式}

将这些质数从小往大输出，然后输出最多能装下的质数个数。

#### 说明/提示 {#说明-提示}

#### 代码 {#代码}

```c++
#include <algorithm>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <map>
#include <math.h>
#include <queue>
#include <set>
#include <stack>
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>

using namespace std;
vector<int> sieve(int n)
{
    vector<bool> isPrime(n + 1, true);
    vector<int> primes;

    for (int p = 2; p * p <= n; p++)
    {
        if (isPrime[p])
        {
            for (int i = p * p; i <= n; i += p)
                isPrime[i] = false;
        }
    }

    for (int p = 2; p <= n; p++)
    {
        if (isPrime[p])
        {
            primes.push_back(p);
        }
    }

    return primes;
}
int main(int argc, char* argv[])
{
    ios::sync_with_stdio(0); // 加速输入输出
    int L;
    cin >> L;

    vector<int> primes = sieve(L);
    int sum = 0;
    int count = 0;
    for (int prime : primes)
    {
        if (sum + prime <= L)
        {
            cout << prime << endl;
            sum += prime;
            count++;
        }
        else
        {
            break;
        }
    }

    cout << count << endl;
    return 0;
}
```
